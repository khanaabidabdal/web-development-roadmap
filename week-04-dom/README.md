# Week 04 — JavaScript DOM Manipulation and Events

This week of my 16-week web development roadmap focuses on making webpages interactive using **vanilla JavaScript**. Building on Week 03 JavaScript fundamentals, I practiced DOM selection, event handling, forms, dynamic rendering, and event delegation, then combined them in an Employee Management Dashboard.

- Select, inspect, and update HTML elements using DOM APIs.
- Respond to clicks, input changes, and form submissions.

- Create and remove elements dynamically.
- Use event delegation for buttons generated at runtime.
- Separate application state from the DOM view.
- Implement CRUD operations, statistics, search, and filtering.
- Test empty states, editing edge cases, and responsive layouts.

## Day 06 project — Employee Management Dashboard

The dashboard supports:

- Registering an employee with a name and department.
- Displaying employees in a table generated by JavaScript.
- Editing employee name and department.
- Deleting an employee and toggling active/inactive status.
- Showing total, active, and inactive employee counts.
- Searching by name and filtering by status and department.
- Displaying a message when no records match the filters.
- Closing the edit form when the employee being edited is deleted.
- A mobile-first layout with a horizontally scrollable table on small screens.

### How it works

The `employees` array is the source of truth. User actions change that array, and `renderDashboard()` refreshes statistics and renders the filtered employee list. Filtering does **not** remove records from the source array.

### Run locally

1. Open `week-04-dom/day-06/index.html` in a modern browser.
2. Add an employee, then try Edit, Toggle, and Delete.
3. Combine name, status, and department filters.
4. Use browser DevTools to test mobile, tablet, and desktop widths.

No server or package installation is required for this browser-only exercise.

### Known limitations

- Data is stored in JavaScript memory; refreshing restores the initial records.
- There is no database, authentication, or backend API.
- Validation is intentionally basic for this learning project.
